## 4. Decisions the card did not make
- **Assumed user-agent formats (all guesses, marked as such in comments and tests):** Feedly `Feedly/1.0 (+http://www.feedly.com/fetcher.html; 12 subscribers; like FeedFetcher-Google)`; Inoreader `Mozilla/5.0 (compatible; Inoreader/1.0; +http://www.inoreader.com/feed-fetcher; 3 subscribers; )`; NewsBlur `NewsBlur Feed Fetcher - 5 subscribers - https://www.newsblur.com/site/123/x`; Feedbin `Feedbin feed-id:123 - 4 subscribers`; The Old Reader `Mozilla/5.0 (compatible; theoldreader.com; 2 subscribers; feed-id=abc)`. BazQux, Miniflux and Tiny Tiny RSS are matched by name only, with invented examples.
- N must be 1 to 1,000,000: "0 subscribers" counts nothing.
- The unknown-aggregator fallback skips the boilerplate tokens `Mozilla` and `compatible`, otherwise every `Mozilla/5.0 (compatible; X; 3 subscribers)` would file under "Mozilla". Tokens are capped at 40 characters by the card's own pattern.
- Bot pattern: the card's list plus `scan`, `probe`, `libwww`, `httpclient`, `pingdom`. `feed` is in it, so a Feedly agent is a bot for R1 and R3 (R2 ignores it).
- Referrer: a trailing dot on the host is stripped; a Referer over 8192 characters is skipped; IP literals are detected after `URL` normalises hex and decimal spellings (tested).
- The cap applies to `record_feed` and `record_referrer` only. `record_view` keys are whitelisted paths with a valid id, and unknown ids are 404s, so a client can't grow it. The cap is per table, month and language, via `INSERT ... SELECT ... WHERE EXISTS OR count < cap ... ON CONFLICT`, still one statement. `report` prints a "Note:" line for a month and language whose table holds 500 or more rows.
- better-sqlite3 refuses reused numbered parameters (`?1` with a positional array); the two capped upserts use named parameters.
- Session-cookie check is a regex on the cookie name with a boundary, `(^|;\s*)__Host-imnstr_session=`, built from `SESSION_COOKIE` so the name can't drift.
- `/fa` redirects (308) and is not counted, since it isn't a 200.
- `reset-content` also counts and reports `episode_link` rows, though they go by cascade.
- AC-47 scan test: names of the record tables are allowed in `lib/record.ts`, the middleware and the two CLIs (reset-content counts the tables by name), `migrations/` and `tests/`.
- Colour schemes (house rule 8): the pages the new tests request are server-rendered identically in both schemes (CSS `prefers-color-scheme`, no server branch), so the tests run both languages only.

## 5. Where the plan, card or brief was wrong or vague
- Card: "the Feedly agent" for the integration test is a single guess; the real string is unknown until MS3's subscriptions.
- Brief's AC-46 regex `ip|addr|agent|ua|cookie|session|visitor|user` is fine on the current columns, but would flag any future column containing `ua` or `ip` inside a word. Not a problem today.
- Plan §5 B8 lists `podcast` as a page but the route is B7's: `/podcast` is a 404 today and uncounted; the whitelist already names it, so B7 needs no change here. Verify after B7 that `/fa/podcast` and `/podcast` count.
- Card says the middleware is "after the ETag middleware"; Hono's ordering means the ETag middleware wraps it and our `next()` returns before the 304 conversion. That is what makes a 304 count; the tests prove it.
- The card says CLI errors print the usage; `parseArgs` errors (unknown flag) are mapped to the usage too, which the card did not spell out.
