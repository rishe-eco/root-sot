## What to build

Plan §5 B6 is the spec. The founder decided at this launch that **one lane builds it, with the bare editor first**: make your **first commit** the editor working on its own, with publish and save on the happy path and its tests green, so that it could deploy alone. Then add "nothing lost" in later commits. Report the first commit's hash.

**The editor** (part 1, the first commit)
- **The ProseMirror packages from §6.6** (`-model`, `-state`, `-view`, `-commands`, `-keymap`, `-history`), and nothing else: no input rules, menu or placeholder plugin.
- **The schema mirrors `shared/doc.ts`** and imports its rules (`isAllowedHref`, `stripXmlForbidden`); don't copy them. `doc > paragraph+`, marks `link{href}` and `highlight`.
  - Highlight parses from `<mark>` only, so pasted `<b>`, `<strong>` and `<em>` become plain text.
  - A link with any other scheme is dropped to its text.
  - Pasting strips the XML-forbidden characters (**S-5**).
  - Before every send, run `normalizeDoc` on `doc.toJSON()` (**S-4**).
- **Keep the editor behind one component** (`value`, `onChange`, `lang`, `readOnly`). PD-7's fallback, a textarea read by `docFromText`, could then replace it without touching anything else. Don't build the fallback.
- **The language control comes first,** on new text only, and starts at `GET settings`' `lastLanguage`. It sets `lang` and `dir` on the title and the body (AC-42). An edit shows no control: `PUT` never changes `lang`. After a publish, the new empty editor starts in the language just used.
- **Labels and placeholder:** a real `<label>` "Title (optional)"; the body labelled (visually hidden is fine); the placeholder "What did you learn? Say it so someone else would get it." (AC-18), drawn with a class and CSS `::before`.
- **The toolbar:** **Link** and **Highlight**, in full words (HIG #6).
  - Link wraps the selection and opens the address in place: "Link address", Remove link and Done (plate 8, F5). The caret in an existing link opens the same field.
  - An address `isAllowedHref` refuses is refused at the field. No `window.prompt`.
- **Bidi (PD-8, AC-48):** run `isolateRuns` over each text node as `Decoration.inline(…, { nodeName: 'bdi', dir, lang })`.
- **No `style` attribute anywhere.** The CSP is `default-src 'self'` and refuses them, and a violation fails `admin-support.ts`'s `problems` check. ProseMirror's required CSS (`prosemirror-view/style/prosemirror.css`) goes into `admin.css`.
- **The slot:** `Home` shows the empty editor whenever nothing is being edited (W1: the editor always comes first). Edit puts the entry into the same editor, inside B5's frame and its header lines. `DocView` goes if nothing uses it; `Runs` stays.
- **Actions** (plates 7, 8, 12):
  - new text: Save draft (secondary) and Publish (`btn--primary btn--solid`);
  - a draft: the same two;
  - a published entry: Unpublish (B5's) and Save.

  Publish can't be tapped twice. While it is in flight its label is "Publishing…" and the editor is read-only, until the server answers.
- **Requests** (PD-11):
  - New text sends `POST entries` with the `publishKey`, made by `crypto.randomUUID()` at the first keystroke.
  - Once the server answers with a row, work by its id: Save is `PUT entries/<id>`, and publishing a draft is `PUT`, then `POST …/publish`.
- **Confirmations:**
  - "Published. It's out there.", with the URL, Open and **Copy link**. Copy link turns to "Copied" for `limits.copiedMs`, then back (F16). The editor empties only after the server confirms.
  - "Saved. The live entry shows this now. Its link and date haven't changed."
  - "Draft saved. It's in Entries, not on the site. Open it from any signed-in device." The button then reads "Saved".

**Nothing lost** (later commits; PD-12)
- **`admin/buffers.ts`,** pure, with the storage injected. It holds the states new, editing, kept, confirmed and discarded, and three buffers in `localStorage`, keyed by kind (`entry`; B7 adds `episode`):
  - unsent: key, language, title, doc;
  - edit: id, title, doc;
  - kept.

  Each buffer is written on every change and cleared only after the server confirms. "Kept on this phone" is the only draft signal (W7). **No count anywhere:** no words or characters, no "saving…", no "saved 2 min ago".
- **AC-43, Edit over unsent text:**
  - the unsent text becomes kept text, and the notice says "Your unsent entry is kept. It comes back when you save or cancel here.";
  - after Save or Cancel, it comes back: "Back to your unsent entry. It isn't published.", with Discard;
  - Discard asks once more.
- **A closed tab (J3.3):** when the page opens with unsent text, show "You left something here. Unsent text from earlier on this phone. It isn't published.", with Put it back and Discard. An edit buffer found when the page opens is offered back too: choose the wording and report it.
- **No network:**
  - "Not published yet. The connection dropped. Your text is kept on this phone." with Try again, sent with the same key. **Only a tap retries;** nothing publishes by itself.
  - Save: "Not saved. The connection dropped. Your changes are kept here, and the live entry hasn't changed."
  - Unpublish: "Not unpublished. It's still live."
- **An expired session (W6, plate 9):** a 401 must not unmount the editor.
  - `api()` gains an option that keeps the editor's writes from firing `whenSignedOut`; every other call keeps that behaviour.
  - Show "Not published yet. You were signed out after an hour idle. Sign in to finish. Your text stays right here." and **Sign in and publish** (or "and save").
  - That button runs `signIn()`, not `reauthenticate()`: re-authentication needs a live session, and it answers 401. Then it reruns the action **once**, on the new session and CSRF token. A second 401 shows the notice again and never loops.
  - Pass the new `SessionInfo` up to `Home`, so Passkeys' "this device" stays right.
- **Errors** sit just above the action (W5).

**Measure, don't change:**
- **S-9:** the request size of a body at `limits.bodyMaxBytes` with a link on every word. If it stays under Nginx's `1m`, report the number. Don't touch `deploy/nginx/imnstr.conf`: it's a stop file.

**Tests:** plan §5 B6's list, in `tests/e2e/editor.spec.ts` and `tests/unit/buffers.test.ts`.
