## What to build

Plan §5 B8 and PD-20 are the spec. This settles what they leave open.

**`lib/record.ts`** (house rule 4: the record's one file)
- `countView`, `countFeed`, `countReferrer`, `report(db, from, to)`, `clearRecord(db)`, and the pure parsers they use, exported for unit tests. Writes are single upserts.
- **What a request is**, by path only, a whitelist: `/` and `/fa/` → `landing`; `/log` and `/fa/log`, any `?before=` → `log`; `/podcast`, `/fa/podcast` → `podcast` (404 until B7, so not counted yet); `/log/<id>` with `isId(id)` → the id; the two `feed.xml` → feed. Anything else is not counted. Language from `c.get('lang')`.
- **The month** is `YYYY-MM`, Gregorian, Latin digits, in `SITE_TZ`. Add `recordMonth(instant, timeZone = env.siteTz)` to `lib/dates.ts`, with unit tests across the Tehran month turn (e.g. 31 Oct 20:29 UTC is October, 20:31 is November).
- **Bots:** an empty user agent, or one matching a case-insensitive pattern (`bot`, `crawl`, `spider`, `slurp`, `preview`, `monitor`, `uptime`, `headless`, `lighthouse`, `curl`, `wget`, `python`, `go-http-client`, `java/`, `okhttp`, `node-fetch`, `axios`, `facebookexternalhit`, `feed`, and the like) is skipped for **R1 and R3**. `curl` matters: `deploy/checks.sh` fetches pages after every deploy.
- **R2** applies to feed requests only, and **ignores the bot pattern** (every feed reader is a bot). The count is `(\d+)\s+(subscribers?|readers?)`. The aggregator name comes from a table of known ones matched by substring (Feedly, Inoreader, NewsBlur, Feedbin, The Old Reader, BazQux, Miniflux, Tiny Tiny RSS), otherwise the first product token (`[A-Za-z][\w.-]{0,39}`), otherwise `other`. Keep the month's **highest** N (`MAX`), not a sum. Ignore N over 1,000,000. Unit-test each format below and mark every one in a comment as **a guess, to be confirmed by real fetches** (plan §5 B8, trap 1): `Feedly/1.0 (+http://www.feedly.com/fetcher.html; 12 subscribers; like FeedFetcher-Google)`, `Mozilla/5.0 (compatible; Inoreader/1.0; +http://www.inoreader.com/feed-fetcher; 3 subscribers; )`, `NewsBlur Feed Fetcher - 5 subscribers - https://www.newsblur.com/site/123/x`, `Feedbin feed-id:123 - 4 subscribers`, `Mozilla/5.0 (compatible; theoldreader.com; 2 subscribers; feed-id=abc)`.
- **R3** comes only with a counted R1 view. The domain is the `Referer`'s hostname, lowercased, one leading `www.` removed. Skip: no `Referer`; a scheme other than http or https; the site's own host (from `env.origin`, with and without `www.`); an IP literal (it could be a reader's own network); a host over 253 characters.
- **Bounded growth.** A client can send any `Referer` or user agent. Add `recordKeysPerMonth: 500` to `lib/limits.ts`: past that many rows for one table, month and language, a new domain or aggregator is dropped, and existing ones still count. `report` says when a month hit the cap.

**The middleware**, in its own file (e.g. `lib/record-middleware.ts`), mounted with one line in `app.ts` at B1's marker, after the ETag middleware.
- It runs `await next()` first, then counts only when the method is `GET` (HEAD is skipped) and the handler's status is 200. Because it sits inside the ETag middleware, a conditional request that leaves as a 304 is counted like the 200 it stands for. That is deliberate: feed readers mostly poll conditionally, and R2 would otherwise go stale. Test it both ways.
- **Any request whose `Cookie` header carries `__Host-imnstr_session` is not counted** (PD-20, D-8). Check the name's presence only: never read the value, never touch the session table. The response is byte-for-byte the same either way.
- **It never throws into the page and never logs the request** (house rule 9). A failed count is dropped silently, or with `console.error` of the error alone. Test it: drop a record table in a test database, and the page still answers 200 with the same body.

**CLIs**, in `scripts/` like `seed-entry.ts`, with npm scripts `report` and `reset-content`:
- `report --from 2026-11 [--to 2027-01]`: `--to` defaults to this month in `SITE_TZ`; both months are inclusive; a bad month or `from` after `to` prints the usage and exits 1. It prints, per language: views per page, then per entry (path plus the title or opening words, from `entry`; "(no longer an entry)" if the row is gone), most first; the highest subscribers per aggregator over the period; and referring domains, most first. Where R2 is empty, it says **"No feed reader reported subscribers in this period."**, never an estimate (change note 02).
- `reset-content`: deletes `entry`, `episode` (its links cascade past `episode_last_link`) and the three record tables, in one transaction. It keeps `credential`, `session`, `auth_code`, `auth_throttle` and `setting`. **Without `--yes` it prints what it would delete, as row counts, and changes nothing.** Test it with a published episode that has one link, seeded by SQL.
- Add both to `deploy/README.md`, in the `dc exec -T imnstr node --import tsx scripts/…` form, with "take a backup first" before `reset-content`.

**Tests** (integration with `testApp`, both languages; unit for the parsers)

Then seed the record with distinctive numbers (e.g. 731942) and assert that no public page in either language, `/admin`, and no signed-in admin API `GET` contains them.
