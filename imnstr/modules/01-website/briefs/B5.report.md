## 4. Decisions the card didn't make

- **`app.ts` needs no new line.** The entry router mounts inside `adminApiRoutes`.
- **Refusal plumbing.** `STATUS` and `refuse` stay in `routes/admin-api.ts`, because `admin-copy.test.ts` parses that table. The entry router is a function taking `{refuse, readJson}`, which avoids a runtime import cycle. B7 can do the same.
- **S-11 and unknown `auth/*` paths.**
  - Signed in, an unknown `/admin/api/...` path answers `{"code":"NOT_FOUND"}` 404, for any method.
  - A known path with the wrong method answers the same way.
  - Signed out it stays 401.
  - An unknown `/admin/api/auth/*` path answers the public site's HTML 404 (`c.notFound()`), signed in or out, as before. The catch-all deliberately defers to it.
- **POST `entries` answers 200 for a new row and an existing key alike**, with the same bytes, so a retry can't tell. An existing key writes nothing, and `last_language` is not written either. The key is lowercased before use. A body that is not a JSON object is `REQUEST_INVALID`. `publish` absent means false, and a non-boolean is `REQUEST_INVALID`.
- **PUT ignores `lang`, `state`, dates and `publishKey` entirely**, so no `LANG_INVALID` on PUT. NOT_FOUND is checked before the body is.
- **`publish` covers republish.** There is no separate `republish`: `COALESCE(first_published_at, now)` keeps the original date. Publishing a published entry changes nothing, and `last_language` is written only when the publish changed state.
- **Insert-and-publish:** insert as a draft, then update to published, inside one transaction. An episode can't be born published (its trigger needs a link), so one path serves both kinds. An episode asked to publish with no link rolls back whole (tested).
- **BODY_REQUIRED versus DOC_INVALID.** A body that `normalizeDoc` leaves with no paragraphs (empty paragraphs only, or `content: []`) is `BODY_REQUIRED`. Whitespace-only text is too. Schema, XML-forbidden characters (in text and link addresses) and size are `DOC_INVALID`. The size is of the stored, normalised JSON in bytes.
- **Title:** trimmed, blank means none. A non-string or any `\p{Cc}` (newline included) is `REQUEST_INVALID`. There is no length cap, since the card names none.
- **List.**
  - Sort key `COALESCE(first_published_at, created_at) DESC, id ASC`.
  - An unknown or malformed cursor is `NOT_FOUND`.
  - The response is exactly `{entries, olderBefore, now}`.
  - Rows are `{id, lang, title, excerpt, state, wasLive, firstPublishedAt}`.
  - The excerpt is 120 characters, cut at a word, with "…" when cut (the plate shows "…" inside the quotes). The client adds the curly quotes.
- **Single entry response** is `{entry:{id, lang, title, body, state, wasLive, firstPublishedAt}}`. `body` is the document. Publish and unpublish answer the same shape.
- **Admin behaviour.**
  - After Unpublish, the frame stays open as the "was live" draft: the notice, the republish notice and Publish together.
  - After Publish, it becomes the published frame with "Published, at <date>." and Open.
  - The list reloads when the frame changes an entry, and each time the section is opened. A collapsed list asks for nothing. Loaded "Older" pages collapse back to page one on a reload.
  - Links in the read-only body are real `<a target=_blank rel="noopener noreferrer">`.
  - Publish uses `btn--primary btn--solid`, which is ink fill (HIG #5, plate 8), though `.btn--primary` alone is the highlighter in `admin.css`.
  - Two pills on a row stack within 5rem so a long name keeps its room at 360 px.
  - The `NOT_FOUND` message is now generic ("That isn't there any more.") because it serves passkeys and entries.
- **Copy I wrote** (plate 8 gives none): the empty state "Entries you write will be listed here."; the three new refusal messages; "Opening…". Persian is not involved (the admin is English).
- **`/__test/entries`** takes `state`, `createdAt` and `publishKey`; a draft with `firstPublishedAt` is a "was live" row.
- **Deploy check:** the entries 401 and the unknown-path 401, added to `deploy/checks.sh` and the README line.
