## What to build

Plan §5 B7 is the spec. This card settles what the plan leaves open, against the code.

**Server**
- **`lib/episodes.ts`** reads and writes, through `lib/publish.ts` (house rule 4). An episode's JSON: `id`, `lang`, `name`, `description`, `tags` (one or two strings), `date` (`YYYY-MM-DD`), `links` (`{label, url}[]`, in order), `state`, `wasLive`, `firstPublishedAt`.
- **S-3, publishing new text in one request:** an episode can't be born published, and its links need the row first. Give `createOrGet` an optional step that runs **inside its transaction, after the insert and before the publish**; episodes insert their links there. Entries pass nothing and don't change.
- **Links travel whole.** `PUT episodes/<id>` carries the full list, and the server makes the table match it in one transaction. **Don't build `DELETE episodes/<id>/links/<n>`:** Remove is part of the edit, so Cancel undoes it (plate 11 has Save under Remove). Never delete every link and then insert: `episode_last_link` fires on a published episode. Insert the new rows first, then delete the old. **An empty list on a published episode is `LAST_LINK` (409).** Report the plan's route as dropped, in item 5.
- **PD-23, in this order, at publish:** `NAME_REQUIRED`, `DESCRIPTION_REQUIRED`, `TAGS_ONE_OR_TWO`, `LINK_REQUIRED`. A draft needs only a language. **`LINK_NOT_HTTPS`** applies to every save: the URL must parse, and its scheme must be `https:`. Blank tags are dropped. A link with a URL and a blank label is `REQUEST_INVALID` (the form never sends one). The triggers stay as the backstop. Map their `RAISE` messages to the same codes, and prove each trigger by SQL (house rule 6).
- **Guards in `lib/limits.ts`**, each `REQUEST_INVALID`, with the field's `maxlength` to match (as F-16 did for the title): name 1,000, description 10,000, label 100, URL 2,000, links 20. Strip XML-forbidden characters from every text field. Keep the description's line breaks.
- **The date is a calendar date**, never an instant. The server fills a missing date with today in `SITE_TZ`. `lib/dates.ts` gains today-in-the-zone and a formatter for a `YYYY-MM-DD` date that never converts a zone: "10 Oct 2026" in English, Solar Hijri in Persian digits in Persian. Admin list rows follow the year rule (AC-31). Pin them with exact strings, including a clock at 23:30 UTC and a run under another `SITE_TZ`.
- **Routes:** `routes/admin-episodes.ts` holds `GET/POST episodes`, `GET/PUT episodes/<id>` and `POST episodes/<id>/publish|unpublish`, mounted inside `adminApiRoutes` after the guard (**S-12**). Add the codes to `STATUS`. `GET episodes` returns `today` and `now`: the bundle never reads the time. `routes/podcast.tsx` holds `/podcast` and `/fa/podcast`. `app.ts` gains one line for each file.
- **Order:** `date DESC, id ASC`, on the public page and in the admin list alike. `?before=` follows PD-25: a malformed, unknown, unpublished or other-language cursor is a 404.

**The public page** (plate 4; `/fa/` from plate 13)
- The show's name and intro, then **the show links from `content/site.<lang>.ts`, under the intro on every page**: empty, one episode, 21, and the "Older" page (AC-29). The desktop frame's "Listen wherever you like" block repeats them; don't build it.
- Episodes: the date and tags, the name, the description, and one pill per link, all with `target="_blank" rel="noopener"` (AC-33). **Every pill is the same:** no icons, since the founder hasn't supplied any marks (§5 trap 1). Names, descriptions, tags and labels go through `lib/bidi.ts` (AC-48).
- **Microdata (PD-19):** `PodcastEpisode` with at least `name`, `description`, `datePublished` and `partOfSeries`. Report the full set; the verify runs validator.schema.org.
- The empty state "Episodes will be listed here, with links to listen." (W11), in both languages. "Older episodes", working with script off (AC-30). `current="podcast"` in the nav. The landing page already links here.
- New public strings go in `locales/`. Persian copy is placeholder (F-2).

**The admin** (plates 11 and 12)
- **The Podcast section,** between Entries and Passkeys, collapsed like Entries. It holds **New episode**, then the list: date, or "—" for a draft that was never published; name; a "draft" or "was live" pill; Edit; and "Older". A row with no name yet says so; choose the words. The empty state is "No episodes yet.". One form serves new and edit, inside the section.
- **The form:**
  - Language first, on new episodes only.
  - Name, Description, Tag and "Second tag (optional)" (F17), and Date as `<input type="date">`, starting at the server's `today`.
  - Links: Label above URL, with YouTube and Castbox as chips that fill the label. **+ Another link.** Remove on each link when there are two or more; none on a published episode's only link, which shows "A published episode keeps at least one link. Add the right one, then remove this.".
  - A URL that isn't https is refused at the field, with the fix built from the person's own text: "This link needs to start with https://, like https://youtu.be/abc123. Everything else you typed is still here." Never add the prefix yourself.
  - New and draft: Save draft and Publish. Published: Unpublish and Save.
  - Confirmations from the plates: "Saved. The episode keeps its date and its place."; republish names the date: "Published, at 3 Oct 2026. It's back in its place on the podcast page.". Write the new-publish and draft-saved wording on the entry's pattern, and report it.
- **S-19, reuse rather than copy.** Move what both forms need (`useWriter`, `FailureNotice`, `LanguageControl`, `DiscardDialog`, `Offer`, `newKey`, `NEEDS_TAP`, `UNANSWERED`) out of `composer.tsx` into one shared file, with no change in behaviour. Make `buffers.ts` generic over what a buffer holds: one reducer, and a reader and a "has content" check per kind. Add `admin/episode-writes.ts` in `writes.ts`'s shape: the key at the first keystroke, then by id; a retry after a lost answer follows with `PUT`.
- **The language stays fixed while a send is unanswered** (`NETWORK` or `UNEXPECTED`, no row known), and the key is never replaced (PD-11, B6 review fix 1).
- Failures sit above the actions (W5). Only a tap retries. Signing in over the form runs `signIn()`, then reruns once. The signed-out copy follows F-16: "Not published yet. You were signed out. Sign in to finish. Your episode stays right here." The offline copy is plate 12's. Edit over an unsent episode keeps it, and a closed tab's episode is offered back (AC-43, J3.3), in episode words.
- **No count anywhere** (house rule 1): no "3 episodes", "2 links" or "saving…".

**Measure, don't change:** **S-9**, the largest episode request under the guards, pinned in `request-size.test.ts` beside the entry's. Don't touch `deploy/nginx/imnstr.conf`: it's a stop file. Also give `dist/admin/admin.js`'s size, raw and gzipped, before and after.
