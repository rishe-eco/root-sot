## 4. Decisions the card did not make

- **The unsent buffer carries the row's `id`** (card: key, language, title, doc). Without it, a tab closed after Save draft reopens, posts the same key, and the server answers with the old row *untouched*, which would silently drop edits made since.
- **Kept text is a stack**, not one slot. Two events can park a text while another is parked (offered back and ignored, then Edit; or two edits in a row). One slot would overwrite and lose one.
- **A page that opens with unsent text sets it aside (to kept) at once** and offers it, rather than leaving it in the buffer. Otherwise the first keystroke in the empty editor would write over it. **Put it back swaps** with whatever has been typed since, so neither is lost.
- **The edit buffer is written only while the text differs from the entry** (and cleared when it is typed back to equal), so a page never offers back "changes" that are not changes.
- **The wording for an edit buffer found at open** (card: choose and report): **"You left changes here. Edits to an entry, from earlier on this phone. They aren't saved, and the entry hasn't changed."** with **Put them back** / **Discard** (asks once more). Put them back opens the entry in its frame with the changes over it.
- **Cancel, or Edit on another row, with unsaved changes asks first** ("Leave without saving? The changes to this entry aren't saved yet. If you leave, they're dropped, and the entry stays as it is." Keep editing / Leave). Not in the card: without it one stray tap on Cancel throws an edit away, which AC-43's spirit forbids. Cancel with no changes closes at once.
- **Save or Publish in an edit with text kept: the frame closes** and says what it did ("Saved." or "Published…") above the unsent entry, which is back with "Back to your unsent entry." (the card's "after Save or Cancel it comes back"). With nothing kept, the frame stays as plate 8 draws it.
- **Language:** locked once a row exists (a PUT cannot change it). If it changes after a request was sent with the key and before any row came back, the key is regenerated, because the server would answer a retry with the row in the language first sent.
- **A retry after the text changed:** `POST` answers an existing key with the row as it was, so if its title or body differ from what is in the editor the client follows with a `PUT`, and with a publish if the row is not yet published. If the server answers a Save draft with a published row (an earlier publish whose answer was lost), the editor treats it as published.
- **A failure stays until a write succeeds** ("Not published yet" is still true); only refusals about the text (`DOC_INVALID`, `BODY_REQUIRED`…) clear when the person types. **BODY_REQUIRED is checked in the browser** (`docHasText`) before any request.
- **Failure copy** beyond the plates: "Not saved." for Save draft too; for an edit of a draft "Your text is kept on this phone"; a **storage-refused variant** ("…this browser isn't keeping a copy, so leave this page open"), and "Kept on this phone" is hidden then, because the page must not claim what is not true.
- **No "Saving…" label** on Save or Save draft while in flight (the card forbids "saving…"); the buttons only disable. Publish says "Publishing…" as the plate does.
- **A cancelled passkey sheet** shows the existing "Not signed in. Try again when you're ready."; other sign-in codes show their refusal. The failure notice stays, so the way back stays.
- **Link field:** shown for a new link without Remove link (only an existing one has it); Done with an empty address closes without changing anything; an address that `isAllowedHref` refuses (so also a bare `example.org`) is refused at the field with "That address can't be used. It has to start with https://, http:// or mailto:."; Link with nothing selected says "Select the words to link first." After Done the field stays shut while the caret is in that link, and opens again when it moves out and back in (so typing inside a link does not keep reopening it).
- **The tools and actions are a sticky "dock"** at the foot of the editor, so with the keyboard up they stay in reach; ProseMirror's `scrollThreshold`/`scrollMargin` are set from the dock's measured height so the line being typed scrolls above it, not under it.
- **Composition guard:** the bidi decorations are not drawn while a keyboard is composing, and are drawn again 60 ms after `compositionend`. A guess for Android; see item 6.
- **The toolbar is a labelled group**, not `role="toolbar"`, which would promise arrow-key movement it does not have.
- **Title:** control characters and XML-forbidden characters are dropped as they arrive.
- **Copy link** falls back to selecting the address when the clipboard is refused. **Open** is a plain same-tab link, as B5's was.
- `crypto.randomUUID` has a `getRandomValues` fallback for a non-secure context (untested; the site is https).
- **Header of a draft** stays "Draft" (plate 12's "saved from phone" would need to know the device).

## 5. Where the plan, the card or the brief was wrong, vague or incomplete

- **Two tests forbade `localStorage` outright** (`house-rules.test.ts` and `assets.test.ts`, from B4b's "keep nothing in the browser"). The card does not mention them. I changed them: `localStorage` may be named only in `admin/browser-storage.ts`, and a new test pins that `buffers.ts` writes exactly `imnstr:<kind>:unsent|edit|kept` and that neither file mentions a session, token, csrf or cookie; the bundle test still bans `sessionStorage`, `document.cookie` and `indexedDB`. Please review this as a rule change.
- **`admin-copy.test.ts` banned the word "left"** (against "3 attempts left"), which collides with plate 9's "You left something here." Narrowed to a digit-led count.
- **ProseMirror's own stylesheet cannot be copied as it is:** it holds `#8cf`, `px`, `left` and `right`, which `house-rules.test.ts` forbids in the admin CSS. I wrote the part this editor reaches (the base rules, hide-selection, draggable, the separator image) in `admin.css` with tokens and logical properties, and left out the rules for lists, code and node selections, which the schema cannot produce.
- **The plan (§5 B6) says a 401 opens the re-authentication dialog in place; the card says `signIn()`.** The card is right: re-authentication needs a live session. I followed the card, and did not use `withReauth` or `ReauthHost`.
- **The plan says "Copy link … and View"; the plates say Open.** Used Open.
- **A "no time, no count" rule and plate 9 both use "an hour idle"** in the signed-out copy. I kept the plate's words; the limit is not an elapsed time, but a reviewer may want it checked against house rule 1.
- **The title has no length limit** (`readTitle`). Nginx's `1m` therefore protects the app from a huge title; the body cannot reach it. Not changed.
- **`admin-support.ts`'s `signedInAdmin` could not be called twice at once** (it expected one `.passkey` row), which AC-44's two-contexts test needs. Fixed.
- **`tests/globalSetup.ts` did not watch `shared/` or `lib/bidi.ts`/`i18n.ts`**, which the bundle imports; fixed (item 2).
- **B5's e2e tests asserted the read-only frame** (`.doc`, `.frame__title`, no `contenteditable`, link `target`/`rel`). Updated to the editor. The new editor's links have no `target` or `rel`: they are not followed inside an editable region.

## 6. What I could not verify, and what would

The composition guard and the 60 ms redraw after `compositionend` are untested guesses. *Would verify:* the founder's phone check (V-7); the fallback decision (PD-7) stays his.
- **The sticky dock with a real on-screen keyboard.** I tested a 360 × 400 viewport (the card's stand-in) and 180 px; iOS's keyboard overlays rather than resizes the viewport and may hide a bottom-sticky bar. *Would verify:* the same phone check.
- **E1 / M3** (30 s warm median, five runs per language) and the **cold bundle load** (+70 KB gzipped): not measurable here.
- **In-place sign-in with a real phone passkey**, including hybrid; I used Edge's virtual authenticator.
- **Copy link with a real clipboard permission prompt**; Edge ran with the permission granted.
- **Screen reader behaviour** (the live regions, the `aria-placeholder`, the group label), keyboard focus order beyond what the tests check, and **forced-colors** for the editor's `<mark>`. *Would verify:* step 9's VoiceOver and TalkBack pass.
- **Two browser tabs on one device** sharing the buffers: not handled, not tested (one writer, PD-12).
- **A CI run**, and the deploy checks: not mine to run.
- No stop rule applied; I did not reach twice the size.
