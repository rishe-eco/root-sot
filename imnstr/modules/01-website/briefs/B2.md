## What to build

Plan §5 B2 is the spec. These points settle what it leaves open, or correct it against the code:

- **Image (S-6).** `node:24-slim`, `npm ci --omit=dev --ignore-scripts`. better-sqlite3 loads its prebuilt Linux binary, so **no toolchain and no build stage**: this replaces the plan's "build stage with the toolchain". Confirm `node_modules/better-sqlite3/prebuilds/` holds a `linux-x64` glibc build, and name it in item 4.
- **The server runs through `tsx`** (`node --import tsx server.ts`, as in `.env.example`); there is no build step (PD-4). `tsx` is a devDependency now: move it to `dependencies`, or `--omit=dev` breaks the boot.
- **`.dockerignore`**: `node_modules`, `.tmp`, `.git`, `.claude`, `.env*` except `.env.example`, `data`, `backups`, test output. Without it, `COPY . .` puts the Windows `node_modules` over the image's.
- **Container:** `NODE_ENV=production`, user `node`. The healthcheck uses `node -e` with `fetch` on `/healthz`; slim has no curl. Compose: as in the plan, plus `restart: unless-stopped`, `mem_limit: 256m` (the box has 1.2 GiB to spare), and a second volume, `/srv/imnstr/backups:/backups`. `.env` on the server sets `DB_PATH=/data/imnstr.db` and `PRELAUNCH=1`. Add `data/` and `backups/` to `.gitignore`, since the repo is cloned at `/srv/imnstr`.
- **The backup CLI doesn't exist yet.** Write `scripts/backup.ts`, using better-sqlite3's `db.backup()` to a path given as an argument, then `PRAGMA integrity_check` on the copy; exit non-zero on failure. `deploy/backup.sh` runs it through `docker compose exec -T`, into `/backups/imnstr-<UTC stamp>.db`, deletes files older than 14 days, and then runs `rsync -e ssh` to `$BACKUP_REMOTE`. If that is unset, it says so on stderr and exits 1, so cron reports it. Commit it executable (`git update-index --chmod=+x`); `.gitattributes` keeps it LF.
- **Nginx 1.18:** `listen 443 ssl http2;`, not `http2 on;`. Listen on `[::]` too, as root-app does. **No `default_server`.** `limit_req` goes on `/admin/api/auth/` now (B4a fills it). No `add_header` (PD-18).
- **Certificates without certbot editing the repo's file.** Ship `deploy/nginx/imnstr.conf` as the final TLS config, pointing at `/etc/letsencrypt/live/imnstr.com/`. Ship a port-80-only `imnstr.bootstrap.conf` for the first `certbot certonly --nginx -d imnstr.com -d www.imnstr.com`, then swap it out. This replaces the plan's `certbot --nginx` and its sync trap; say so in item 4.
- **`deploy/README.md`:** first-time setup, including `chown 1000:1000` on `data` and `backups`, the symlink, and the bootstrap conf. Then routine deploys (config §7), the CLIs through `docker compose exec`, the cron line, **restoring a backup into a scratch container**, and the checks after each deploy: `nginx -t` **before every reload**; `curl -I` on `/`, `/fa/` and a 404; root-app answering. Never `systemctl restart nginx`; reload.
