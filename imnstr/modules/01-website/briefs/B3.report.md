## 4. Decisions the card didn't make
- **Paragraphs must hold at least one non-empty text node** (`text+`, not `text*`). The plan's "paragraph+ > text" doesn't say. B5 and B6 can loosen it. `docHasText` is exported for B5's `BODY_REQUIRED`.
- **Order is `first_published_at DESC, id ASC`**, as the plan literally says, with an explicit `(t < ct) OR (t = ct AND id > cid)` keyset. Tested across a same-millisecond boundary and with a page size of 19.
- **A cursor is validated as an entry of the same language that is published.** Anything else gives the language's 404. The "Older entries" link is `?before=<id of the last entry shown>`.
- **Bidi rules:**
  - A URL (`https?://`, `mailto:`, `www.`) becomes `<bdi dir="ltr">`, minus trailing punctuation (ASCII and Persian).
  - In Persian, a Latin run becomes `<bdi lang="en">`. It starts at a Latin letter or digit and joins words with ` . - _ ' / : & + # @`. It must contain a letter, so lone digits are left alone.
  - In English, an Arabic-script run becomes `<bdi lang="fa" dir="rtl">`. It includes ZWNJ, Persian digits and `، ؛ ؟ « » . - :` between words.
  - Isolation is per text node, so a run that crosses a mark boundary is isolated in two parts.
- **An empty feed's `<updated>` is `now()`**, because Atom requires one. Otherwise it is the newest `updated_at` (PD-24).
- **An untitled entry's page has a visually hidden `<h1>`** holding its date, so every page has a heading. This is the same string the feed uses.
- **The feed title date** is a new `formatFeedTitleDate`: "13 October 2026" and "۲۸ مهر ۱۴۰۵". The design says "written in full", and `formatEntryDate` always carries the time.
- **`<time datetime>`** is on the date links, as `feedDate` with the site offset. It is not a count.
- **`POST /__test/entries` takes `{entries: [...]}`** (a batch of 21 is one call) and answers `{ids}`. Each item has `text` (the `docFromText` markup) or `body` (a document). Refusals are the test-only code `ENTRY_INVALID`.
- **The seed CLI** takes the database from `DB_PATH` through `lib/env.ts`, prints the new entry's path, and exits 1 with a usage line on bad arguments.
- **Removed `latinName`** from `SiteContent`, because `isolate` now does what it flagged. The unit test that asserted it went too.
- **Persian-in-English runs use `--font-read-fa`** (Vazirmatn, Estedad). Without it they would have fallen back to a system font.
- **The empty state has no eyes**, which are B9's.
- **Install:** `npm install` fails here in node-gyp, because there is no Windows SDK. better-sqlite3 ships a prebuilt binary, so `npm install --ignore-scripts` works. I reverted the lockfile change it makes.

- **Plan PD-8** says `isolate` "wraps each run in `<bdi>`". It doesn't say what attributes a run carries. The design's `<bdi lang="en">` is what I followed.
- **`tests/integration/pages.test.ts`** (B1) had `/log/feed.xml` in a list of "unknown paths give one 404". Changed, because the route exists now.
- **Recheck of the Persian placeholder copy:**
  - There is no inline Latin left that the page doesn't isolate.
