IMNSTR.com — wireframes · draft 1

Module imnstr/modules/01-website/ · Phase 4 · wireframes. Low fidelity: layout, content and states only. No brand, type or colour decisions; those are step 4b (Claude Design). Every step of J1–J5 in 03-journeys.md §2 and every state in its §3 table is drawn below; plate 13 maps each step to its frame. Phone frames stand for 360 CSS px; the admin is drawn phone-first because the spec makes it so (§4.2).

Grading. Every frame is proposal. Captions cite journey steps (J1.7), spec sections (§4.2) and acceptance criteria (AC-15) from 02-spec.md. Anything drawn in a dashed purple box is a Suggested gap (G1–G9, journeys §4): not a requirement, drawn as an option so the founder and 4b can see what accepting it would cost on screen. Remove the box and the frame still meets the spec.

1Landing — who this is, the projects, two ways in

The landing page is edited in the code repo (journeys decision 1), so it has no admin counterpart and no empty state of its own. It is a single column on a phone: name and one paragraph, the projects as a plain list, and the two ways in. The log link carries no count and no "latest" date; a date here would show a gap to anyone who looks.

2The log — empty, one entry, three, and long

The same page at four amounts of data. Newest first, each entry its date, its title if set, its body in full (AC-2). The date is the entry's link to its own URL. Nothing between entries marks time passing: no month headings, no gap spacing, no "3 weeks later" (AC-5). With few entries the page stays a short column; it never stretches to fill the screen or apologises for being short. Paging is "Older entries", not page numbers, because "page 2 of 5" is a count.

3An entry, the 404, and the feed

The entry page is where a follower arrives (J4.1): the link in a message is their first sight of the site. The spec lists the entry's content but no way out of it; the shared header line and footer that G5 suggests are drawn as an option. The 404 is the one page unpublishing makes routine; its designed form is G7. The feed is not a page but is drawn as a reader would show it, because AC-3's "untitled entry takes its date as its title" is only visible there.

4The podcast page — empty, one link, several, long

A listener's whole visit is this page (persona E). Each episode: name, date, description, one or two tags as labels (not filters, spec §7), and a row of platform links showing only the links that exist. Known platforms (YouTube, Castbox) have an icon; an unknown label shows as text alone, in the same pill. Episode order is by the episode's date, newest first.

5Admin setup — the first passkey

The admin before any passkey exists. Server shell first, then a page that does one thing. Until a passkey is registered, every other admin route behaves as if signed out (AC-8).

6Sign-in — passkey only

The only thing between C and the editor (J2.1). One button; no username, no password field (AC-9). The failure message is the same every time and slows down with repeated failures (AC-11). After sign-in C lands on the page they asked for, which is almost always the editor.

7The admin — one page, ready to write

Layout call (journeys J2.2 left it here): the editor is always the first thing on /admin, empty, with its prompt as placeholder. Below it, three collapsed sections: Entries, Podcast, Passkeys, and Sign out. The dated list of entries is never in first view, so its top date can't announce a gap. Section headings carry no counts ("Entries", never "Entries (9)"). On a phone with the keyboard up, the editor and the Publish button are all that show.

8Admin — entries: find, fix, unpublish, republish

Entries opened from the collapsed section. Every entry is told apart by date and title, or by its opening words if untitled; drafts carry a "draft" chip, published entries none (J2.6). Newest first. Editing opens the entry in the same editor at the top of the page, with the action changed from Publish to Save.

9Writing on a phone when things fail

Nothing typed is lost (§4.2, AC-16). Every failure frame keeps the text in the editor, in full, editable, and says in plain words whether it is published. Errors sit directly above the Publish button, where the eye already is, not in a banner at the top that the keyboard hides.

10Passkeys — add, tell apart, remove, recover

The Passkeys section of /admin. Adding or removing asks for a fresh sign-in first (AC-11). The spec has no names on passkeys; without G2 the list can only show what the browser reports and the date it was added, which may not tell a phone from a laptop. Both versions are drawn.

11Admin — the podcast form and its list

The Podcast section of /admin: the list of episodes, newest first, and one form for new and edit. One link row is shown; "Add another link" adds rows. One link is enough to publish (journeys decision 3). The date defaults to today and, unlike an entry's, may be changed: it orders episodes and feeds datePublished (§4.4).
