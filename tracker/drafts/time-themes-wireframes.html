Time Themes — wireframes

Draft 1 · a Time Theme is a recurring, tag-bearing span of time that softly surfaces matching actions — it never blocks anything. Tags are one shared vocabulary across Project · Interval · Routine · Action · TimeTheme. These are lo-fi mockups to react to, not final UI.

1Tag manager — the shared vocabulary

One user-scoped list. Each tag has a name + colour (the colour is what paints the timeline band). Renaming/recolouring propagates everywhere the tag is used, because everything references the tag by id, not by spelling.

2Tagging the four source entities

The same chip picker appears on Project, Interval, and Routine editors (and the Action editor, §3). Tags set here flow down onto the actions these produce or hold.

3Tags on the action — locked vs editable

This is where the rule you set becomes visible. A gathered action shows its inherited tags read-only. A standalone / project action lets you edit them (project ones arrive pre-filled).

4Time Theme editor

A theme = tag(s) + a time-of-day span + the same recurrence control the interval editor uses. No outcome, no estimate, no steps, no goal/project link — it is only a shaped, recurring stretch of time.

5The payoff — the day, shaped

On the timeline, themes are colored bands drawn behind your actions. During gathering / Pre-day, actions whose tags match the band they fall in surface to the top of that slot with an affinity tick. Nothing is forced — a non-matching action can still sit anywhere.

6Gathering / Pre-day — surfacing in the picker

When you’re assigning start times to a day’s gathered actions and you tap into a themed slot, matching actions rise to the top of the list; the rest stay reachable below a divider.
