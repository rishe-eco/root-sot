## 4. Decisions the card didn't make

1. **Carry-over records the look-back when the new period is saved.** The card says "Done" sets `lookbackSeenAt`, but "Start a new period with these" is a second exit from the look-back. If it didn't record, `deriveState()` would return `"lookback"` again after the new period was created, and the person would land back on the look-back. So `FocusPage` calls `RECORD_FOCUS_LOOKBACK` (with whatever answer was picked, or null) after `createFocusPeriod` succeeds, then refetches. Cancelling the form returns to the look-back and records nothing.
2. **Estimate sent with every day.** `updateAction` is called with `tbd` and `estimatedTimeMinutes` together. For an action that already has an estimate, the existing value is sent back unchanged. Both the card and the plan only required this for the no-estimate case.
3. **Minutes validation** is whole numbers 0–1440 (`parseMinutes`). The server's check is a number from 0 to 1440, and the GraphQL type is `Int`, so fractions are refused client-side too. 0 is allowed, as on the server.
4. **Popover details.**
   - The grid's `min` is today, so past days can't be picked.
   - Save needs a day that differs from the current one.
   - I added a Cancel button (the plate shows only Clear day and Save).
   - Clear day shows only when the action has a day (the plate shows it on a "No day" row; sending `tbd: null` there would do nothing).
5. **No carry-over button when everything finished.** "Start a new period with these" is hidden when there are no unfinished projects, because there would be nothing to carry. An empty Finished or Not finished list is omitted rather than shown empty.
6. **Add and Cancel buttons.** The plate shows "Cancel / Add" in the inline form. I added `focus.add`, plus `focus.completed`, `focus.undo`, `focus.cardMenu` (the ⋯ button's aria-label) and the other keys listed in the locale diff.
7. **Persian copy** is draft, informal register, کار for action, Western digits. The look-back question and its two answers (مسیرم روشن است / عقب افتاده‌ام) are my wording for "oriented / behind"; this is the one the founder should look at first.
8. **Existing-test mock changes (not test changes).** In `FocusPage.test.tsx`:
   - `ConfirmDialog` is now mocked as a button that renders when `open` (it was `() => null`), so Remove can be confirmed.
   - `date-picker-grid` is mocked with one button that picks today+3.
   - `mockCall` gained handlers for `ToggleAction`, `UpdateAction`, `AddAction`, `UpdateFocusPeriod`. `ToggleAction` flips `done` in the fixture so the refetch reflects it.
   - No existing test body changed, and all of them still pass.
