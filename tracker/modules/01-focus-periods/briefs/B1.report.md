## 4. Decisions the card didn't make

- **Migration name.** Prisma timestamped it `20261020200425_add_focus_periods` (machine clock).
- **Title messages** (not in §6.2): `Title is required.` (same wording as tags/time themes) and `Title can be at most 120 characters.` Trim happens in the service.
- **Validation order** on create/update: title, then range, then the 30-id count, then overlap, then the added projects (ownership `Not found`, then done). Cheap checks first. The 30-id limit counts distinct ids (a repeated id counts once, and is stored once).
- **Look-back validation order:** `ensureOwned`, date key, answer, then "after the period ends". `answer` omitted is treated as null. Re-recording is allowed and overwrites (the card's `seen` is just `lookbackSeenAt` set again).
- **Overview semantics (PD-9):** the most recent ended period is found first, then returned as `lookback` only if unseen. An older unseen period never replaces a seen newer one (tested).
- **`addedAt` order within one save.** `setProjects` creates join rows one at a time with `addedAt = now + index` ms, so the order the caller listed new ids in is kept (one `createMany` would stamp them all alike). Ties are broken by `projectId` in the `projects` resolver.
- **Transactions.** Create and update run the project writes in an interactive `$transaction` with `timeout: 30s` (default 5s is too tight on this disk); overlap and cheap checks run before it. A refused project rolls back the create (tested). The overlap check and the write are not in one transaction: two concurrent creates could both pass. SQLite serialises writers, and the app is single-user per account, so I accepted it; a unique constraint can't express a range overlap.
- **Where the rules live.** Resolvers are thin: `ensureOwned` on the period, then the service. `FocusPeriod.projects` returns `Project` rows (not join rows) and includes `actions`, `goal`, `milestone { goal }`.
- **Ownership of period ids passed to `updateFocusPeriod`** is checked in the resolver; the service trusts it (documented in its comment).
