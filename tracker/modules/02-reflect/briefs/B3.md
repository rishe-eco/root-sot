## What to build

What §5 B3 says, with these settled against the code:

- **No SDL or resolver change.** `ReflectInterpretationOffer`, `ReflectFauxOffer` and both result types are already in `typeDefs.ts`. The resolvers in `mutations.ts` pass `move`'s and `saveMoment`'s results straight through. Fill the two `null`s in `entry.ts` and nothing else in the graphql layer.
- **The fold stays byte-identical.** `ARABIC_FOLDS` and `normalizeForMatch` in `services/reflect/catches.ts` must be the same as the copy in `reflectContent.unit.test.ts`, which guards that no trigger nests across families (open-work). Copy them from `noticing/catches.ts` unchanged, and say in the docblock that the test holds a third copy.
- **Packs.** Take the versions from `pinnedVersions` in `state.ts`, and the locale from `DIALS.practiceLocale`, never `ctx.locale` (D-16). Use `getReflectPack` for the interpretation and `getFeelingsNeedsPack` for the faux feeling. An entry exists only after `startEntry`, so `ReflectState` exists: update it, don't upsert.
- **`lastCatchAt`** is a JSON string, `{ "interpretation"?: ISO, "faux"?: ISO }`. Parse it defensively, as `parseLastCatchAt` in Noticing does, so a corrupt value means off cooldown. Write the date from `new Date()`. The cooldown is `(Date.now() - last) / day >= DIALS.catches.<kind>.cooldownDays`.
- **"Differs from the stored one".** Read the moment at `position` before the upsert. Detect only when `norm(patch.feeling)` is a non-null string and isn't equal to the stored `feeling`. Both catches run inside the existing `withUserLock` callback. The surface write is one `prisma.$transaction([...])` over the entry and the state.
- **The offers.** `fauxOffer` is `{ position, ...composeCatch(fnPack, hit.conceptId) }`. If `composeCatch` returns null, there's no offer and nothing is written. `interpretationOffer` is `{ word, sentence }`, and nothing else leaves the server (PD-13).
- **A move to the current step** returns early with no offer, as it does now. Only `to === "reality"`, one step forward from `feelings`, runs the matcher.
- **The import fence (AC-26)** goes in `reflectFences.unit.test.ts`, over every file in `services/reflect`. Any import from a path ending `services/noticing/…` or `noticing/catches` fails. An import from `feelingsNeeds/distinctions` may name only `detectFauxFeeling`, `composeCatch`, and `type` imports. Plant `maybeCatch` and `catchAllowed` once each, and watch it fail.

## Decided here

| # | Decision | Why |
|---|---|---|
| 1 | Matching is per sentence. A trigger that spans a sentence break doesn't match. The longest trigger across all sentences wins, and the sentence returned is the first one that holds it. | §5 B3 says to split before normalizing (D-13), and that leaves no sentence to return for a span. |
| 2 | The returned `sentence` is the original substring with surrounding whitespace trimmed and its terminator dropped. Nothing inside it is changed. | "The sentence is the person's own" (PD-13). Trimming is the least change that reads cleanly. |
| 3 | If neither v1 lexicon holds a nested pair in one family (`en` doesn't), the nested-trigger unit test uses a small inline fixture pack. The `fa`, ZWNJ and Arabic-keyboard cases use the real draft `fa` pack. | AC-31 asks for the behaviour, and the compiled cache is keyed per pack object, so a fixture is honest. |
| 4 | Branch `reflect-b3-catches`, slot A. | No other lane is live, and B3 changes no schema. |
