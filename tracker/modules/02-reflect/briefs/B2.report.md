## 4. Decisions the card didn't make

- **Enum mapping in `typeResolvers`.** `ReflectStep`, `ReflectMet` and the others map `NOT_SURE` to `not_sure` and so on, so services and columns see only the stored lowercase form and a bad value is refused by the schema.
- **Ownership inside the services.** Services call `ensureOwned` from `graphql/auth` with `{ user: { id } }`; resolvers pass `ctx.user.id`. This matches Noticing's services, which check ownership inside.
- **All Reflect writes for one user run under `withUserLock("rfl-entry:" + userId)`**, not only start. That makes the position-count check atomic with the write; the unique key stays as the backstop. `ensureReflectState` runs outside that lock, in the resolver, before `startEntry`.
- **A `replacing` that isn't the open entry's id** (stale, foreign or unknown) returns the open entry, closes nothing and leaks nothing.
- **Moment and reading `position`:** non-integer, negative, `>= 3`, or past the next free position give `An entry holds at most three of those.` The same upsert updates an existing position.
- **Own feeling or need bound (60)** is applied to `feeling` and `need` whatever the source.
- **Pre-check arguments:** `null` and omitted are the same (untouched); any non-null value off the `precheck` step gives the step refusal. Saving a scene or story is allowed on any step of an open entry.
- **`answer`** gives `Not found` for a stranger's id first, then the answer refusal for open, stopped, or already-answered entries.
- **`storyStart`** is 80 UTF-16 units, dropping a trailing half surrogate pair, so a lone surrogate never leaves the server.
- **`reviewStatus`** on `reflectHome` and `reflectContent` is the Reflect pack's alone, not F&N's palette pack.
- **`metOptions.not_sure`** is `notSure` in the GraphQL type.
- **`prompts`** is fully typed (`ReflectPrompts` and five sub-types) rather than JSON. `limits` also carries `storySoftLine`, `ownWord` and the caps.
- **The SDL fence's field check** also refuses `lexicon` on a Reflect output type (the card's `precheck*`, `afterAnswer`, `outcome`, `*SurfacedAt`, plus `lastCatchAt`, which §6.5 lists).
- **A through-the-schema test** uses `ApolloServer.executeOperation` (the app's own server class). `graphql()` from the `graphql` package fails here with a dual-module error (the "Ensure that there is only one instance of graphql" message), because the ESM and CJS copies differ.

**Canon this makes stale** (reviewer's, not mine): `tracker/canon/02-architecture/02-graphql-api.md` (the 14 operations, the session-only rule, the types) and `03-frontend.md` is unchanged. `01-data-model.md` and the decision log owe B1's items only; this stage has no schema change.
