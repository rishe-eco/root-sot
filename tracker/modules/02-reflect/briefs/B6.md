## What to build

**The plan's B6 section is out of date: it isn't client only.** Spec 0.2 moves the list rule and the past-entry type into B6 (§6.1's correction). The API half:

- `api/src/services/reflect/entry.ts`: `LISTABLE` becomes *closed, with any written text*, the same fields `holdsWrittenText` reads in `client/app/components/reflect/types.ts` (scene, story, close; a moment's `whenText`, `feeling` or `need`; a reading's `reading` or `camera`), as one Prisma `where` with `some` on the children. It is used by `hasPast`, `listPast` and `getPast` (which tests `story == null` today).
- A row is `{ id, createdAt, firstWriting }`, replacing `scene` and `storyStart` (AC-37, AC-46). `firstWriting` is the first writing in step order (decision 2), cut by the existing surrogate-safe `storyStart` helper at `DIALS.storyStartChars`. Take the children ordered by `position`. Select only the columns the label needs, so no full story leaves the list (AC-46).
- `reflectPastEntry` returns a new `ReflectPastEntry` type: `ReflectEntry` without `step` (AC-48). Add it to `typeResolvers.ts` as `ReflectEntry` is. Rename `ReflectOpenEntry.hasStory` to `hasWriting` with the same rule (AC-53), and change its caller (`ReflectHomePage.tsx`, `types.ts`, `queries.ts`, `ReflectHome.test.tsx`).
- `reflectFences.unit.test.ts`: `ReflectPastEntry` joins the guard list, and a new fence refuses `step` or `outcome` on it. Plant `step` once to see it fail.

The client half is the plan's plates 10 and 11, with these notes:

- **Reads go through `useApi`, not Apollo** (as B4 built; plan correction to B4). Drop the plan's trap about evicting from Apollo, keep the D-9 comment `ReflectEntryPage.tsx` carries, and after a delete `navigate("/tools/reflect/past", { replace: true })` so Back can't return to the deleted entry.
- **Not found:** `call()` returns `null` and `error` is `"Not found"` for both a stranger's id and a deleted one. Show the one line and *Back to Reflect* on that message; any other error shows a plain couldn't-load line. Don't reveal which case it was.
- *Show older* passes the last row's id as `before` and appends.
- Labels and lines are new `reflect.past.*` keys in both locales; field content gets `dir="auto"` (AC-64).
- Routes go in `client/app/protectedRoutes.tsx` beside B4's two, still unlinked from Tools (PD-5).

**e2e:** move `MODULE_KEYS` to one file under `client/e2e/helpers/`, imported by `freshUser.ts` and `globalSetup.ts` (open-work, from B5). The new tests use `signUpFreshUser`.

## Decided here

| # | Decision | Why |
|---|---|---|
| 1 | Whitespace-only text counts as written: listed, and labelled as it is | B2's rule 2 never trims; the calm close already offers Delete for it, so hiding it would recreate D-4. The row still carries a date, so it can be opened and deleted. Open-work row, for verify |
| 2 | The label's order after the spec's five: the first moment's `feeling`, then its `need`, then the first reading's `camera` | The spec's five can all be empty while a feeling word or a camera line exists, and such an entry is listable. The row needs text. A spec gap, for verify |
| 3 | `hasStory` is renamed `hasWriting` | The old name would mean something else (§6.1 correction allows the rename) |
| 4 | One shared `MODULE_KEYS` file for the e2e | Open-work row owed to "the next card that adds an e2e user" |
