## 4. Decisions the card didn't make

- **The scratch database is per API port:** `file:./prisma/p<apiPort>-e2e.db`, which lands at `api/prisma/prisma/p4110-e2e.db`, not `e2e.db`. Two slots in one worktree would share one file, and slot B's `--force-reset` would wipe slot A mid-run. It still ends in `e2e.db`, so the guard holds; `*.db` ignores it (`git check-ignore` confirms).
- **The credentials file is per API port** (`client/e2e/.auth/e2e-user.<apiPort>.json`). Otherwise slot B's globalSetup overwrites slot A's token, and each token is valid only in its own API's database. `client/.gitignore` therefore ignores the `.auth/` directory.
- **`outputDir` and the html report folder are per slot** (`test-results/<port>`, `playwright-report/<port>`), so two runs don't clobber each other's artifacts.
- **The API wait URL is `/.well-known/apollo/server-health`, not `/graphql`.** See 5.
- **Vite cache per web port:** `vite.config.ts` gained `cacheDir: process.env.E2E_VITE_CACHE_DIR ?? "node_modules/.vite"`; the web `webServer` entry sets `node_modules/.vite-e2e-<webPort>`. Dev behaviour is unchanged. See 5.
- The timeout is 120 s for the API (it runs `db push` first, about 8 s, then ts-node) and 60 s for web.
- Canon made stale: `config.md` §2 and §4 (lane table, "e2e is not lane-safe", the scratch-config recipe), as the card says. `CLAUDE.md`'s "e2e isn't isolated yet" paragraph too, and `03-engineering/01-testing.md` if it describes the e2e setup. No schema change.
