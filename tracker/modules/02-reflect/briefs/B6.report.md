## 4. Decisions the card didn't make

1. `firstWriting` picks, for each field in order, the first child in position order that has text, not strictly `moments[0]`. A first moment left empty with a second one written still labels by the second's *when*. The spec says "the first moment's when"; the two agree whenever the first moment has text. Without this, a listable entry could get an empty label.
2. `getPast` and `hasWriting` use a JS predicate (`holdsText`) rather than a second query, to keep one `findUnique` on that path (D-9 timing). `LISTABLE` (a Prisma `where`) and `holdsText` are the same rule written twice; the integration tests cover both with the same cases, and the client's `holdsWrittenText` is a third copy.
3. `listPast` combines the list rule and the cursor as `AND: [LISTABLE, cursor]`: both use `OR`, and a spread would have let the cursor overwrite the rule.
4. `getPast` strips `step` from the object, as well as the type having no such field (the card's test "the result has no `step`").
5. Not found on the entry page is read from `getLastError()`, not the `error` state (the state is stale in the render that follows `await call()`).
6. The moment line on the entry view shows feeling, need and Met (plate 11 shows Met). Met uses new keys `reflect.past.met.*` (Met / Not met / Not sure; برآورده شد / برآورده نشد / مطمئن نیستم), not the served content's `metOptions`, so the page needs no content query. A moment with only a Met value and no text is left out (the same rule as `holdsWrittenText`).
7. The entry view shows a reading and its camera line as two lines, the camera muted, with no arrow (plate 11 draws `←`, which reads wrongly in English and mirrors in `fa`).
8. The list has no back link in the header; its *Back to Reflect* shows only in the empty state, as plate 10 draws it. The entry view has *Past entries* at the top.
9. The three e2e walks run at 1280, 360 and 180 px like B4's; they sign up their own users and delete nothing, so the shared user's `beforeEach` cleanup is unaffected.
10. Persian strings are my own drafts in the informal register (see item 6 for review): "نوشته‌های قبلی" matches B4's `reflect.home.past`; "چه شد" for *What happened*; "پاکش کن" for *Delete*.

Canon made stale: root-sot `tracker/modules/02-reflect/` (build plan §6.1's GraphQL table: `ReflectPastRow`, `reflectPastEntry`'s return type, `ReflectOpenEntry.hasStory`); `tracker/canon/02-architecture/02-graphql-api.md` if it lists those Reflect types.
