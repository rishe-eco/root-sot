# Working — active, in-play documents ("living layer")

These are current working documents, not canon. They change as the work proceeds and graduate into `../canon/` only once stable enough to cite. Grouped by stream below.

## Journey (the self-authorship app)
- **`Learn feels and needs discovery.md`** — Learn Pillar, Module 1 (Feelings & Needs). Intended outcomes + discovery foundation: observable learning outcomes, the "graduation not completion" model, and six discovery hypotheses (H1–H6) to convert into Mom-Test / JTBD interview threads. Precursor to interview criteria. *Draft v0.1 (2026-07-21).* The 22 Jul session split H6 → H6a/H6b (see canon `../canon/02-pillars/learn.md` / evidence summary and the canon-log).
- **`learn-discovery/`** — the active Learn Module 1 **discovery workstream** (engine Phase 1). Sequential docs, produced one at a time: `01-research-criteria-and-method.md` (done), then method artifacts, then participant criteria. See `learn-discovery/README.md`.
- **`learn-mechanisms/`** — the **mechanism / process-anatomy** track for Learn, parallel to discovery: *how* each of the module's processes actually works (mechanism, system, preconditions, failure modes, observable signals, dials). *Full first pass (2026-08-01) — template + all eight processes worked.* See `learn-mechanisms/README.md`.
- **`learn-build/`** — the **build** track: the development plan for the Feelings & Needs Module 1 **demo** (fully-working, not yet user-tested) — built as a Tracker tool, LLM-free, tiers 1–3 live / storytelling deferred. *v0.1 (2026-08-01).* See `learn-build/README.md`.
- **`impact-build/`** — the **build** track for the **Impact** pillar (named 2026-09-20, from the working name *Others*): Act 1 is need recognition, and the tool is **Noticing** — a repeated practice that trains seeing unmet need in your own immediate environment. Concept + spec + wireframes. Built as a Tracker tool, LLM-free, tiers 1–3; the Environment Scan and Offer Rehearsal are deferred to later acts. *v0.1 (2026-09-20).* See `impact-build/README.md`.
- **`reflect-build/`** — the **build** track for the **Reflect** pillar: Act 1 is **re-seeing a single moment** (the reconstrual lever, `canon/02-pillars/reflect.md` §6), and the tool is **Re-seeing** *(working name)* — tell one moment, mark your reads, look at the camera version of your own story, step back, say what you see now. Concept only. To be built as a Tracker tool, LLM-free, Reflect's own tool rather than Learn Module 1's Tier 4. *v0.1 (2026-09-30).* See `reflect-build/README.md`.

## Root Studio (business/services arm — formerly "Root Dev")
- **`root-website-v3-overview.md`** — the Root website becomes an *application*: public front + authenticated client portal (Contracts, Services, Billing, Support), role-aware backend (Express + GraphQL + Prisma, **Postgres**), minimal operational admin now / full admin later. *(2026-07-21.)* **Note:** its "Contracts is the urgent piece" framing was **stood down on 2026-08-01** — a live first client is no longer the driving milestone (decision log). The rest of the document holds.
- **`root-website-requirements_2.md`** — the v2 build brief & requirements (design tokens, bilingual/RTL, process). **Still holds**; v3 extends rather than replaces it. Keep both. *(2026-07-08.)*
- **`root-website-versioning-and-admin.md`** — spec, **partly built**, extending v3: **independent version control** for the contract and the design (two immutable revision lineages), a **signed contract frozen with amendments**, **design carry-forward** of unchanged approvals, and the **full admin dashboard** that authors them. Written the day root-app first ran on Postgres. Feature 1 is built (V1, 2026-08-02); the dashboard is not, and amendments are still read-only. All three open decisions now closed — **admin-only authorship** (the tracked "revision requested" state deferred as a named refactor) and **free-text amendments**, with structured supersede-Article-N rejected rather than deferred, because it would make the readable contract a *computed* document. *(0.2 · 2026-08-04.)*
- **`root-website-research-lab.md`** — spec (not built): the **Research Lab**, a public bilingual library of referenced + own research under the **Library** section (opens the Root Cast content lock; one strand of the Library, beside Root Cast). Concept tree + list + search, translation provenance, public/private visibility, admin + contributor curation, agent last. Umbrella label locked **Library / کتابخانه** at `/:lang/library`. Its last two open items closed 2026-08-04, and neither was what it had been filed as: the contributor/admin "permission line" is a **capability model over a role set**, and the "per-source rights workflow" is a **required rights field with no default** — which also turned out to be the agent's quote-versus-cite scope, unblocking R4. *(0.3 · 2026-08-04.)*
- **`root-website-build-plan.md`** — **the build order for the three specs above**, plus the foundations none owns but all need (file upload/storage, the staff shell, the role model). Records the 2026-08-01 sequencing: versioning to depth first, the Library second, a live client stood down, demo mode retired, local-disk storage — and, from 2026-08-04, the Review Room third. **F1 (upload/storage) is closed** — design files 2026-08-03, the printable contract 2026-08-04, which also settled that a contract PDF is a *rendering* of a published revision and never the record. **F3 (roles as a set, capabilities as the guard) is built as of 2026-08-05**, which makes **F2, the staff shell at `/desk`, the only unbuilt foundation — all three tracks wait on it.** 0.7 planned the dashboard to its end: track C added, **V1b** added ahead of everything because the draft is still invisible to GraphQL, **F3 rewritten** from one enum value into the app's permission model and moved *before* F2, and every blocking open decision closed. Read this before starting any of the three. *(0.8 · 2026-08-05.)*
- **`root-website-project-lifecycle.md`** — **spec, draft**: the full arc of a client project — first contact to delivery and after — as one object model with two permission views (portal / desk), extracted from the Nahal engagement. Nine recurring frictions (F1–F9) and the mechanism that closes each: the **scope registry** as the spine everything else projects from, review frames that a demo cannot be published without, ratification by a named decider, a symmetric dependency board, subscriptions/invoices, and the product-import panel as the first service. Two decisions parked in §10 — the paid design phase (taken up the same day by ADR 0001) and admin-as-a-product (gate unchanged: the counted admin-request channel). *(0.1 · 2026-09-18.)*
- **`root-studio-business-model.md`** — the **Business Model Canvas** for the sequencing of [ADR 0001](../decisions/0001-studio-first-with-design-wedge.md); the two are one decision in two forms, the ADR saying *what and in what order* and this *how the money and the work flow*. Every block graded **proven / traced / hypothesis** against the single engagement backing it, with the five riskiest assumptions pulled out in §10 so they get tested on purpose. SaaS-to-other-studios is deliberately off the canvas — it is gated. *(0.1 · 2026-09-18.)*
- **`root-studio-lifecycle-build-plan.md`** — **the build order for the lifecycle spec**, under ADR 0001's motion, and the successor to `root-website-build-plan.md` (which is thirteen of fourteen built, its last stage waiting on content rather than code). Six decisions that had to precede any migration — **all answered 2026-09-20**: the registry moves to a **`Project`**; a demo is the **live staging site, embedded, with page-keyed notes** (which reversed the file's own captures recommendation — the cross-origin objection was false for a site Root builds, and the freeze objection only ever bit pixel-anchored annotation); **one customer role**, so the decider is simply the project's customer; dumb interception; the design-machinery reuse narrowed to a spike over page *keys*; and a **`DEVELOPER` role holding `builds.author` alone**, whose migration travels with L1 rather than with the stage that needs it, on F3's precedent. Critical path **L0 · L1 · L2 · L3 · L3b**, the registry to the review loop *closed at both ends*, on the grounds that only one canvas bet is both load-bearing and code; two of the five need no code at all. **L3b** — builds and the resolution ledger — is where the developer writes what happened to each comment and what changed that nobody asked for; it closes a structural gap in the lifecycle spec (the registry cannot know about an unrequested change) and turns out to be the per-item tracker the predecessor plan deferred by name in August. §7.1 records the fact the whole schedule turns on — **no production data yet**, so the migration window is open, and §8 names the three things that would reopen the file rather than amend it. **Final for planning; nothing built.** *(1.0 · 2026-09-20.)*
- **`root-website-review-room.md`** — **spec** as of 2026-08-04, and sequenced by the build plan as track C: a private panel where an invited specialist (psychologist, sociologist, manager) reads **Root's own documents** and **leaves comments**. Sibling to the Research Lab and opposite in every property that matters — private not public, our documents not others', and the reader writes. Its three deciding questions are answered: **snapshot at review time** (and the freeze is a git commit), **one corpus for everyone defined by an allowlist** — which reverses the document's own per-reviewer-grant reading — and **passage-level anchoring**, which the snapshot is what makes safe. *(0.2 · 2026-08-04.)*
