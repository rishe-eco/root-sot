# Impact Build — workstream

The **build** track for the Impact pillar (named 2026-09-20; see `../../canon/02-pillars/impact.md` §2). Living layer.

Act 1 of the pillar is **need recognition**, and the tool that does it is **Noticing**: a short, repeated practice that trains seeing unmet need in your own immediate environment — one place, one person, what you saw, what it might point to, and optionally one small thing.

Where the pillar canon says *what Impact is*, this track answers *what we build, in what shape, and why not the obvious shape.*

**Contents:**
1. **`00-act1-concept.md`** — the concept and its grounding. Why the obvious build (two inventories and a matcher) is ruled out, what the research says the bottleneck actually is (noticing, not choosing), the four-kind survey of what exists, the three tiers, the hard fences, and the two settled seams — third-party data and Learn Module 1. **v0.2 (2026-09-20).**
2. **`01-noticing-spec.md`** — the prototype spec: processes N1–N7, screen/flow (day-one frame, the loop, the log, the catches, graduation, the Reflect handoff), capacity-by-accretion, failure modes as acceptance criteria, dials, data model, milestones, and the pre-registered null. **v0.4 (2026-09-20).**
3. **`02-noticing-wireframes.html`** — low-fidelity wireframes (open in a browser). Day-one frame (beat 1's five steps + beat 2) · the loop (place → person → saw → need → small thing) · close, repeat and sitting · **the log** · the three catches · the graduation door. Companion to the spec's §4.
4. **`03-spine-evaluation.md`** — the **feel-test** for milestone 3, the one risk no later milestone rescues: does the loop feel like noticing, or like filling in a form about a coworker? Four instruments (retrospective think-aloud, AttrakDiff + IMI, an objectification tripwire plus one interview question, the Day Reconstruction Method for transfer) and a **decision rule written before the data**, with the ambiguous outcome named so it can't be read as a pass. **v0.1 (2026-09-20).**
5. **`04-build-plan.md`** — how the spec becomes code in **Tracker**: the file map and route namespace (`/tools/impact/noticing`), the conventions inherited from the Feelings & Needs module and **the one deliberately broken**, why **Noticing authors its own needs palette** rather than sharing Learn's, the data model as it actually lands, the GraphQL surface, the catch engine's per-field matching contract, five test suites — including **`noticingFences`**, which reads the Prisma schema and the SDL as text so the no-search / no-person-index rule fails the build instead of sitting in a doc — and the two gates on the milestone-3 risk. **v0.2 (2026-09-20).**

**Settled inputs (2026-09-20):** built as a **tool inside Tracker** now, migrating to Impact's standalone app later (the Feelings & Needs arrangement); **LLM-free** — the catches run on authored lexicons; **scope = tiers 1–3**, with the **Environment Scan** and the **Offer Rehearsal** deferred to later acts; entries are **private-only with a warning at the point of writing**, and any future sharing requires a de-identification pass; the **needs palette is Noticing's own and wider than Learn Module 1's** — reading a need from outside is a wider job than naming one from inside, and the list has to include needs that invite no offer — with the same need carrying the **same id** in both tools; Module 1 is **not** a prerequisite either way (entry is plural — `../../canon/02-pillars/00-the-loop.md` §5). English-only prototype; the **Persian** pillar and tool names are open.
