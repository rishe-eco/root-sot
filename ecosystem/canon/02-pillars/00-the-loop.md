## 1. One machine, not five tools

The pillars are not a suite of features that happen to share a login. They are one loop, and each is incomplete without the others: Reflect without Organize is navel-gazing; Organize without Reflect is goal-chasing without wisdom; Impact without Organize is good intentions without follow-through; Learn without the rest is skill-collecting without purpose. The loop is the product; the pillars are its organs.

## 2. Why it must face outward

From Core Philosophy §4: the self-view is unreliable and does not correct from the inside. So a closed inward loop — Reflect, Maintain, Learn, Organize all pointed at a self managing itself — is a hall of mirrors, however well-instrumented. **Impact is the outward face that makes the rest true.** It is what turns self-management into self-authorship with a point (Brand §1). This is the structural reason the fifth pillar is load-bearing, not additive.

## 3. Narrow output channels (the thing that keeps them from tangling)

Each pillar emits one kind of thing. The narrowness is the design.

- **Reflect → immediate action only.** If articulation surfaces a need now, act now; otherwise hand off (skill→Learn, future commitment→Organize, recognized need→Impact).
- **Maintain → immediate action only.** Depletion/overcharge recognized now is responded to now; otherwise hand off. No schedules.
- **Organize → tracked future commitments.** The only pillar where time horizons expand and things are tracked over time.
- **Learn → capacity.** Completed capability that makes new action possible; returns to Organize.
- **Impact → recognized needs.** Discovery, not execution: where capacity could meet the world. The *act* is handed to Organize.

## 4. The tight couplings

Most pillar pairs are loosely joined by handoffs. Three are tightly coupled and must be built with the seam in mind:

- **Reflect ↔ Impact — the motive check.** A recognized service opportunity does not become a goal until Reflect audits its motive: compassion and genuine capacity, or obligation and guilt? Obligation-born "service" is stopped here. *(Clarified 2026-10-18: "stopped" means it cannot pass unexamined — the person sees the motive and is offered to reshape or let go. If they still choose it, it is theirs: the motive is recorded and asked about once if the goal goes quiet. Root never authors for the user, and that includes overruling them about their own motive.)*
- **Reflect ↔ Organize — service goals and failure.** Service acts that pass the motive check flow to Organize with the same rigor as any goal (discipline is the container for authenticity, not its enemy). And when a goal fails, Organize handles the structural read (in vs. out of my control) while Reflect handles the emotional and meaning-making read.
- **Learn ↔ everything.** Any pillar that surfaces a capability gap routes it to Learn; Learn returns capacity to Organize. Learn's first module (feelings/needs) is also the on-ramp to Reflect.

## 5. Entry is plural; the loop is not a sequence

Users enter where the need is acute — depleted → Maintain; stuck in a pattern → Reflect; ready to contribute → Impact; a concrete goal → Organize. The loop describes how the organs feed each other, not a required path. Stay long enough in any pillar and it surfaces the need to visit another. Don't let the architecture's coherence pressure a one-size journey.

**One exception, taken on purpose (2026-10-18): the first act.** The very first thing a person does in Journey is one pass through the loop in a fixed order, starting outward — **name a need in the world → reflect on it → check batteries → set the goal → check capacity for that goal → name the one thing that would make it much easier to do.** It always ends in a goal (when capacity is short, a goal that builds it; when no need comes, a noticing practice until one does). Batteries and capacity inform the goal; they never gate it. After the first act, entry is plural again and the person moves in any order. The first act is a single demonstration of the whole machine, not a sequence the loop keeps imposing: it shows each organ once, in the order where each one's output is the next one's input. Why outward first: §2 — Impact is what makes the rest true, so the product opens on it. The cost — a narrower door than "enter where the need is acute" — is accepted as the bet. Spec: `../../working/journey-build/01-first-act.md`.

## 6. The system stays inert; the user grows

Critical, and easy to get wrong: **the system does not learn across users or optimize the loop.** No cross-user pattern-mining, no nudging toward "better" behavior, no accumulating model of what works. That path rebuilds the engagement machine we refuse. Root is a mirror and a container; the intelligence and the growth live in the person, who carries what they learned from one turn of the loop into the next.

## 7. Journey / ماجرا

Journey is the experience that holds all five pillars as one loop (plus the community/content layer, Root-Cast). **It is built loop-first (2026-10-18):** a thin version of the whole loop exists before any pillar is deep, and each pillar deepens inside it. This is the only build order consistent with §1 — if the loop is the product, the loop is what has to be tested first, not last. A pillar becomes a standalone product only if one fits; that is now the open question, replacing *when to merge*. The thin version lives in Tracker (the "child version"). See the decision log, 2026-10-18.
