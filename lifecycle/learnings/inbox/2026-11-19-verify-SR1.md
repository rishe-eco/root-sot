## Probe a shared service primitive for sequences the UI can't reach
**Rule:** When a stage adds a shared server primitive (here `setCrossed`), probe it with call *sequences* its tests don't hold — a repeat call, a double-fire, an already-done state — not just varied single inputs. A toggle-shaped UI hides these, but a crafted call or a two-rapid-click race reaches them, and later stages build on the primitive directly.
**Event:** Probing `setCrossed` with a second cross of an already-moved-to-today action (a sequence no test covered) found it erased the `DayRecord`'s `crossMoved`/`movedFromKey`, breaking the later uncross's restore (AC-18). Fixed on the branch with a failing-first regression test.
**Cost:** a latent AC-18 break in a primitive every SR stage uses; found in ~15 min of probing.
**Scope:** skill `verify`
**Destination:** review-checklist §3 Probes (a line: probe a new shared primitive with repeat/idempotent/racing call sequences, not only single-input edges)
**Urgent:** no

## A card handing a lane a shared component must name which surfaces share its handlers
**Rule:** When a card points a lane at a component used by more than one surface (here `ActionPreview`, whose `showTodayOptions` branch Today also renders), the card should say so in one line — "touching `handleToggle` touches Today too; that's fine/not fine". It turns an investigation into a one-line confirmation and stops a lane half-building an out-of-scope surface.
**Event:** The SR1 lane spent time tracing `TodayPage → ActionPreview → TOGGLE_ACTION` to decide whether the inherited `showTodayOptions` change was in scope (lane report part 7); the review then had to decide the same thing.
**Cost:** lane tracing time; a scope call `verify` had to adjudicate and flag for SR2.
**Scope:** skill `build-phase` (the card draft)
**Destination:** brief-common.md or the card template — a "shared surfaces" line when the stage touches a multi-surface component
**Urgent:** no

## `git worktree remove` on Windows times out deleting node_modules, and a killed remove bricks retry
**Rule:** In an unattended run, don't remove a lane worktree with a foreground `git worktree remove` — deleting its `node_modules` on Windows exceeds the 2-minute Bash limit, and a killed remove deletes the worktree's `.git` file first, so every retry then fails `validation failed … '.git' does not exist`. Delete the directory with a background `Remove-Item -Recurse -Force`, then `git worktree prune`, then `git branch -D`.
**Event:** `git worktree remove .claude/worktrees/sr1-crossing` timed out at 2 min; the retry failed validation because the first run had already removed `.git`; recovered by PowerShell `Remove-Item` in the background then `prune`.
**Cost:** ~5 min and two failed commands mid-landing.
**Scope:** skill `verify` (the main-session landing), repo
**Destination:** unattended.md rule 7 or config.md — the worktree-removal recipe for Windows
**Urgent:** yes — a foreground remove will stall every unattended landing on this machine
