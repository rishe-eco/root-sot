## Tracker's e2e runs on Linux with a scratch config and a scratch database

**Rule:** To run one Tracker e2e spec on the Linux machine, put a config in the ignored `client/.tmp/` that spreads `playwright.config.ts` and sets only `use.channel: "chrome"`. Give the API a fresh SQLite file with `DATABASE_URL=file:<scratch>/x.db npx prisma db push --skip-generate`, so nothing writes to `dev.db`.
**Event:** `playwright.config.ts` pins `channel: "msedge"`, which the ceiling table counts as Windows-only. `goals.spec.ts` passed 4/4 in Chrome this way, and the manage page was screenshotted at 360 px in both languages.
**Cost:** about 15 minutes to set up; it removes a ceiling row for targeted runs.
**Scope:** project (Tracker)
**Destination:** `projects/tracker/config.md` §3 and §7 (the ceiling row's fallback), through the founder
**Urgent:** no

## A fix that extracts a helper needs its reproducing test on the old surface

**Rule:** When a fix moves logic into a new helper, the test that reproduces the bug has to render the component the user saw. A test of the helper itself can only fail with "is not a function" against the merge base, which reproduces nothing.
**Event:** Against `e90ceda`, both `goalStatusKey` tests failed only as a missing export. Only `ManageGoalStatus.test.tsx` failed on the defect itself (`found … goalManage.statusIgnored`). `/debug` had written that test, so the reproduction held.
**Cost:** none this time; without the component test, the review would have had to write one.
**Scope:** skill `debug`
**Destination:** `skills/debug/reference.md`
**Urgent:** no
