## A loose shared check stays green until it is tightened, so tighten it before the milestone, not at it
**Rule:** When a review finds that a shared test helper passes too much (here, the hit-area helper counted a hit on the control's row as a hit), the owed fix should go to the next lane rather than wait for a milestone. Tightening it at the milestone found three app defects that a milestone can't fix (milestone step 3), so the milestone stays open on new lane work and the strict helper has to sit on a branch to keep `main` green.
**Event:** `verify SR6` filed the helper as "MS2 (a shared helper: its rerun is a milestone's)". At MS2 the full suites were green (e2e 129/129), and the strict helper on the four specs that use it failed 5 of 53 tests on three controls under 44 px (the cross-out control is 42 px because its `::before`'s inset counts from the padding box, inside the border). The control has shipped since SR1.
**Cost:** about 15 minutes of reruns; a lane stage owed, and three defects carried from SR1, SR2 and SR6 to the milestone.
**Scope:** skill `verify` (stage step 3, which items go to a lane) · project tracker
**Destination:** `lifecycle/skills-plan.md` §3 `verify` (a shared check found too loose goes to the next lane, with a *needed by* of that stage; founder's yes)

## A failing hit-area probe should name what it hit
**Rule:** A geometric check that fails should say what it found as well as where. The helper now names the element at the missed point and whether it is an ancestor, so a failure reads as a defect or a probe artefact without a second run.
**Event:** The first strict run said only "missed at 21,0". A second run that named the hit element (`<li data-testid="today-row"> (an ancestor)`) separated the three real misses from capture's timeout (`scrollIntoViewIfNeeded` waiting on a hidden control until the test timed out; now skipped with `isVisible()`).
**Cost:** one extra four-spec rerun (about 2 minutes).
**Scope:** project tracker · e2e helpers generally
**Destination:** `lifecycle/engineering-checklist.md` (a check's failure message names what it found; founder's yes)
