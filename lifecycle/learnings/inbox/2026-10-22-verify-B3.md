## A fence is built from the acceptance criterion's words, not the card's paraphrase
**Rule:** When a card asks for a fence, quote the AC it holds in the card, and have the lane plant one violation for each thing the AC names, not only the names the card lists.
**Event:** B3's card described AC-26's import fence as "nothing from `services/noticing`, only two names from `distinctions`". AC-26 says "no Reflect code reads or writes F&N's tables". An import of `../feelingsNeeds/session` or `state` passed the lane's fence. The review found it, and fixed it in `f031764`.
**Cost:** one review fix; with no review, a fence that looks complete and holds a door open.
**Scope:** method · skill `build-phase`
**Destination:** `build-phase` (a card's fence item quotes its AC)
**Urgent:** no

## A verify commits each fix as soon as it is proven
**Rule:** In `verify`, commit each fix right after it has failed first and then passed, before moving to the next one, so a stopped session leaves no unproven edits behind.
**Event:** The first `verify B3` session was stopped with three edits uncommitted in the lane worktree (a fence widening, a transport test, a removed second read). The resumed session had to reconstruct and re-prove each one against the unfixed code before it could keep it.
**Cost:** about 10 minutes of re-proving
**Scope:** skill `verify`
**Destination:** `verify` step 3
**Urgent:** no

## Heredocs and `sed` mangle backslashes in this harness
**Rule:** Write any file content holding a backslash with the Write or Edit tool, never a Bash heredoc or a `sed` replacement.
**Event:** B3's lane report part 7: two test edits broke when a heredoc halved `\\` and `sed` turned `\n` into a newline.
**Cost:** two broken edits, fixed by the lane
**Scope:** model behaviour · project tracker
**Destination:** `lifecycle/projects/tracker/brief-common.md` (already proposed in STATE.md's carry-overs)
